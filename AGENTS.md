# AGENTS.md

MohammedFawzey's personal portfolio — a single-page Vue 3 app. All content is static and stored in code; there is no backend or database.

## This repo

- Vue 3 (`^3.5`) + Vite (`^7`) + Nuxt UI **v4** (`^4`, not v2) + Tailwind **v4** + TypeScript, VueUse, Lenis, Iconify, Google Fonts via `@fontsource/inter`, `@fontsource/playfair-display`, `@fontsource/jetbrains-mono`. Deployed to Vercel as a static SPA.
- One page: `src/App.vue` composes `HomeLanding`, `HomeProjects`, `HomeAbout`, `HomeSkills`.
- **All site content** — contacts, projects, stack, tools, about, experience, skills groups, header links — lives in `src/constants/index.ts`. "Update CV" = edit that file. Hide a project by setting `show: false`.
- Project card images load from `/public/compressed/<src>.png` (project `src` field maps to the filename), except projects whose `src` starts with `http` (loaded directly); preview screenshots are under `/public/compressed/<src>/`.
- Nuxt UI v4 components are auto-imported (`UButton`, `UBadge`, `UIcon`, `UContainer`, ...) by the `@nuxt/ui/vite` plugin — don't import them manually. `UApp` in `src/App.vue` wraps the app. Everything else is plain Tailwind 4 utility/component classes — don't pull in Nuxt UI components for layout.
- **Your own** components, composables, Vue APIs and VueUse are imported **explicitly** (no auto-import). Use `@/` alias (`src/`). Do not rely on Nuxt-style auto-imports.
- `auto-imports.d.ts` / `components.d.ts` are generated by the Nuxt UI Vite plugin (gitignored) — don't edit or commit them. `.idea/` is WebStorm metadata; don't commit it.
- Icons are Iconify names used via `<UIcon>`; only use collections already installed (`@iconify-json/*` in `package.json`).
- Theme: primary color `orange` (`vite.config.ts` `ui.ui.colors`); light editorial design — Playfair Display headings, Inter body, JetBrains Mono labels; custom colors (`surface`, `on-surface`, `primary` `#a43716`, `secondary` `#346762`, ...) and font/type tokens in `src/assets/css/main.css` (`@theme`). Dark mode: `@custom-variant dark` + `.dark` token overrides in `main.css`, driven by VueUse `useDark` (`src/composables/useTheme.ts`, storage key `portfolio-theme`, `colorMode: true` in `vite.config.ts`), with a FOUC-prevention script in `index.html`; toggle lives in the Header (desktop nav + mobile menu). Tailwind 4 is CSS-first — there is no `tailwind.config.ts`.
- Header nav: each section has an id (`home`, `work`, `about`, `experience`, `skills`, `contact`); header links use `:href="\`#${link.section}\`"` and `HEADERLINKS` in `src/constants/index.ts`. Keep section ids and `HEADERLINKS.section` in sync when renaming.
- Animations are CSS-first (composited `opacity`/`transform` only, no GSAP):
  - `useLenis()` (`src/composables/useLenis.ts`) — Lenis smooth scrolling with `anchors: { offset: 88 }`; skipped entirely under `prefers-reduced-motion` (falls back to native).
  - `useNavbar()` (`src/composables/useNavbar.ts`) — toggles `isScrolled` after 16px of scroll; Header binds `nav-transition` classes for bg/border/shadow/padding.
  - `useReveal()` (`src/composables/useReveal.ts`) — IntersectionObserver adds `.appear` to `[data-reveal]` elements once; `--reveal-delay` supports staggering (project cards use row index). Reduced-motion: reveals shown instantly.
  - Hero entrance: `.hero-enter` + `--hero-delay` in Landing; hover polish via `.project-card`, `.link-underline`, `.btn-primary`/`.btn-secondary`.
  - All of the above styled under `@layer components` + a `@media (prefers-reduced-motion: reduce)` block in `src/assets/css/main.css`. Reuse these composables/classes rather than adding new animation code.

## Working Style

- Inspect only the files relevant to the task before changing anything.
- Implement directly when the request is clear — don't plan, ask clarifying questions, or research obvious choices first.
- Keep changes small and localized; reuse existing code, state, services, components, and patterns.
- Do not modify unrelated files, over-engineer, refactor unnecessarily, or introduce new architecture unless asked.
- Avoid unnecessary sub-agents and broad repository exploration when the relevant files are already known.
- Escalate to deeper investigation and planning only when the task is genuinely complex, ambiguous, or blocked.
- Prefer `grep`/`glob` to locate the relevant method, endpoint, or component before reading a full file. Avoid reading entire controllers, services, or pages when only one function or section is relevant.
- Never start, stop, or restart the `pnpm dev` dev server process for any reason, including to "pick up" code changes, to test a fix, or because a running instance looks stale. Assume it's already running and managed by the user. If a running instance appears out of date or needs restarting, tell the user and let them do it.

## Frontend

- Use `pnpm` (repo has `packageManager: "pnpm@11.21.0"` and `pnpm-lock.yaml`); never npm/yarn/bun.
- Main commands: `pnpm dev`, `pnpm build` (runs `vite build` then `vue-tsc --noEmit`), `pnpm typecheck` (`vue-tsc --noEmit`), `pnpm preview`.
- No lint/test script is configured. For typechecking run `pnpm typecheck` from the repo root; run `pnpm build` or `pnpm dev` first if the Nuxt UI-generated types (`components.d.ts` / `auto-imports.d.ts`) are missing.
- 4-space indentation.
- Vue 3.5 `<script setup>` SFCs. Explicit imports for all non-Nuxt-UI symbols.

## Verification

After implementation:

1. Run the most relevant build/typecheck command (`pnpm typecheck` and/or `pnpm build`).
2. For UI changes, perform one focused browser verification when practical.
3. Verify the changed flow rather than unrelated features.
4. Fix errors caused by the change, then stop — don't repeatedly re-test working, unrelated functionality.
5. Verify via build/typecheck/compile only. Do not start, stop, or restart a dev server to smoke-test an endpoint or page — see the server-process rule under Working Style.
6. If live verification against a running server is genuinely necessary, stop and ask the user to confirm the server is running and up to date, rather than starting or restarting it yourself.
